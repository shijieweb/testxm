## 一、项目是什么

**AI 驱动需求管理平台（第一版前端）** 是一个"AI 主导、开箱即用、最小化落地"的需求管理与研发协作平台。用户首次使用只需配置一个 AI 模型，其余全部使用默认架构和内置提示词；创建项目时 AI 自动优化用户输入、展示默认架构目录，创建后自动初始化项目结构。

### 1.1 核心设计原则

| 原则 | 说明 |
|---|---|
| 单一数据源 | 提示词、架构目录只在全局设置中定义一次，其他页面引用模板名称，不重复书写内容 |
| 全流程闭环 | 配置 AI 模型 → 创建项目 → 自动初始化架构 → 进入故事列表，每一步都有明确数据来源和触发逻辑 |
| 移动端优先 | 移动端优先设计，桌面端自适应 |
| 界面美观 | 具备合理动效（Framer Motion） |

### 1.2 当前已实现功能

| 页面 | 功能 | 状态 |
|---|---|---|
| 项目列表（首页 `/`） | 展示项目卡片、空状态引导、删除项目（带确认弹层）、进入项目 | ✅ 已完成 |
| 设置页 `/settings` | AI 模型配置（API 地址/Key/模型名，可测试连接、可编辑）、默认架构技术栈（只读树形目录）、提示词模板（只读、可展开/复制，7 个模板） | ✅ 已完成 |
| 创建项目页 `/create` | 项目名称/简介/基础用户设想表单、AI 优化项目描述（当前为模拟实现）、优化结果标签展示、默认架构目录预览、创建项目 | ✅ 已完成 |
| 项目详情页 `/project/:id` | 占位页（"项目详情页（开发中）"） | ⚠️ 开发中 |
| 深色/浅色模式 | 全局主题切换（移动端顶栏 + 桌面端侧栏） | ✅ 已完成 |

### 1.3 技术栈

- 前端：React 19 + TypeScript + Vite 8 + Tailwind CSS v4 + Framer Motion + Zustand + React Router 7
- 图标：lucide-react
- 测试：Vitest + React Testing Library + Jest DOM（66 个测试用例，7 个测试文件）
- 状态管理：Zustand（全局 store，无持久化，刷新即重置）
- 后端：**尚未开发**（设计文档中规划为 Python + FastAPI + SQLite）

## 四、如何运行与测试

```bash
cd ai-platform
npm install          # 安装依赖
npm run dev          # 启动开发服务器，访问 http://localhost:5173
npm test             # 运行测试（Vitest，66 个用例）
npm run build        # 生产构建（tsc -b && vite build）
npm run lint         # Oxlint 代码检查
```

**注意**：
- 当前 AI 优化功能为**模拟实现**（`create/index.tsx` 中 `handleOptimize` 使用 mock 数据 + 1.5s 延迟），未接入真实 AI API。
- `testConnection` 也是模拟实现（store 中 800ms 延迟后返回"连接成功"），未真实请求模型。
- Zustand store 无持久化，刷新页面后项目数据丢失。

## 五、接手指南（下一个 Agent 怎么上手）

### 5.1 阅读顺序

1. 先读本文件（`00-项目归档与接手指南.md`）——了解项目全貌
2. 读 `01-项目汇总报告.md`——了解开发过程与决策
3. 读 `02-踩坑经验与进度汇总.md`——了解踩过的坑和当前进度
4. 读 `03-人格角色文档.md`——了解助手的工作人格与协作方式
5. 读 `design/设计文档-AI驱动需求管理平台前端设计方案.md`——了解原始设计意图
6. 需要开发时读 `ai-platform/` 源码和测试

### 5.2 接手第一步：跑起来

```bash
cd ai-platform
npm install && npm run dev
```

打开 http://localhost:5173 验证三个页面（项目列表 / 设置 / 创建项目）能正常渲染和交互。

### 5.3 接手第二步：跑测试

```bash
npm test
```

确认 66 个测试用例全部通过。**本项目严格遵守 TDD 标准**：任何新功能必须先写测试（红灯）→ 实现（绿灯）→ 重构。

### 5.4 接手第三步：理解代码结构

- 状态全部在 `src/store/index.ts`（Zustand），页面通过 `useStore()` 读取
- 路由在 `src/App.tsx`，布局在 `src/layouts/MainLayout.tsx`
- 设置页三个卡片组件在 `src/pages/settings/`
- 测试文件与被测文件同目录（`*.test.tsx` / `*.test.ts`）

### 5.5 接手第四步：了解团队体系（可选但推荐）

`team-system/` 是开发过程中沉淀的 AI 协作方法论体系。如果后续开发仍采用"多角色协作"模式，请先读 `CONSTITUTION.md` 和 `INDEX.md`，了解秘书/PM/前端/后端/测试/运维/军师的角色分工和 7 阶段 SOP。核心规则：

- 秘书只审查不干活，PM 写任务清单，前端/后端/测试执行，运维整理记忆
- 文档未落实不碰代码（需求文档、详细设计文档未经评审通过前不写实现代码）
- 契约先行（接口契约由 PM 制定、秘书批准）
- 每步写日志、收工写记忆
- 并行子代理上限 3 个
- 说真话文化（发现问题必须指出，禁止表面和谐）

## 七、重要约定与注意事项

1. **TDD 是硬标准**：所有功能必须有测试，先写测试再实现。老板明确要求"严格遵守 TDD 标准"。
2. **单一数据源**：提示词、架构目录只在设置页/store 中定义一次，页面引用不重复。
3. **移动端优先**：新增页面需同时适配移动端（顶栏+底部导航）和桌面端（侧栏）。
4. **敏感信息**：本项目归档文件已检查，不含任何 token、密钥等敏感信息。设置页中的 API Key 字段为空默认值。
5. **团队体系**：若继续使用多角色协作模式，遵守 `team-system/CONSTITUTION.md` 的规则；若仅做前端开发，可直接在 `ai-platform/` 内工作。
