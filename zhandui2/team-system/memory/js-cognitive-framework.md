## 角度清单

### ANGLE-001 先验自审
- 核心问题：这个方案/方向/判断，我自己用已有的角度验过没有？有没有从全局和其他角度看过？
- 触发场景：每次向老板汇报或提问前
- 来源：老板现场指出（2026-08-14，秘书问"方向对不对"时老板指出）
- 学习事件：秘书问老板"这个方案对不对"，老板指出你应该先自己审视，不要把未经验证的方向直接问人
- 使用示例：秘书想问"方向对不对"前，先用角度库里其他角度自审一遍，形成自己的判断，再交老板确认
- 领域标签：通用
- 功能标签：决策前校验
- 使用次数：2
- 效果记录：2026-08-14审视v1.8方案，发现4个断点并修复；2026-08-14审视角度库自身发现11个问题，但秘书违规自修（角度库只有军师可写），军师验证后发现其中5处改错，由军师修复
- 可证伪条件：如果秘书连续10次不先自审就直接提问，且没有出任何问题，说明这个角度不需要

### ANGLE-022 错误转检测项
- 核心问题：我上次犯的错，下次执行前查了没有？每个错误必须变成可机械判断的检测项，不是写完检讨就完了。
- 触发场景：军师每次执行任务前、每次自回顾发现问题时
- 来源：军师自回顾序号001（2026-08-14，5项决策被推翻后发现"只记错误不转化检测项"是根本缺陷）
- 学习事件：军师自回顾记录了5个错误（全量归档不压缩/保留10条没算行数/备份N=5没做对比/只看memory没看.team/照搬8条没算篇幅），但只写了检讨没有转化为可执行的检测项。下次执行同类任务时，没有东西提醒"上次在这个地方犯了错"，导致可能重复犯错。发现"错误日志→检测项→角度"的进化路径缺失了中间环节。
- 使用示例：
  **首次使用——把序号001的5个错误转化为5条检测项：**
  - 错误1"全量归档不压缩"→检测项：提归档方案时必须回答"归档后怎么被使用"→检测方法：检查方案中是否写了回溯路径（怎么找、找什么）→通过标准：写出回溯路径
  - 错误2"保留10条没算行数"→检测项：提数字阈值时必须算实际效果→检测方法：检查方案中是否有计算过程（行数/字节数）→通过标准：写出计算过程
  - 错误3"备份N=5没做对比"→检测项：提保留数量时必须算至少2个备选值的实际效果→检测方法：检查方案中是否有≥2个备选值的对比数据→通过标准：写出对比数据
  - 错误4"只看memory没看.team"→检测项：审计文件目录时必须列出所有匹配模式的目录→检测方法：检查是否列出了所有.archive目录路径→通过标准：写出找到的所有路径
  - 错误5"照搬8条没算篇幅"→检测项：提保留条数时必须算条数×单条平均字数→检测方法：检查方案中是否有总字数计算→通过标准：写出总字数

  **角度核心规则：**
  1. 每次自回顾发现的问题，必须转化为一条可机械判断的检测项（格式：错误描述→检测项→检测方法→通过标准），写入js-self-review.md的检测项清单
  2. 军师执行任务前必须读js-self-review.md的检测项部分，逐条对照当前任务是否涉及
  3. 完成前逐条对照涉及的检测项自检，全过才能提交
  4. 某检测项反复出现≥3次→提案为新角度→走正常角度验证流程入库（检测项是角度的种子）
  5. 检测项的进化路径：错误日志（过去式"我犯了XX错"）→检测项（将来时"下次做XX前要查YY"）→角度（永久认知工具"做XX时必须查YY"）
- 领域标签：通用
- 功能标签：执行中监控
- 使用次数：8
- 验证案例：序号001的5个错误转化为DET-001~005后，在序号003~010共8次执行中反复使用：①DET-001在序号004成功拦截老板"直接删不归档"方案（"把归档当终点"第2次出现被拦）；②DET-002检测形式合规实质失效3次达阈值（序号007/008/009），已落实检测方法增强并提案候选ANGLE-025；③DET-012在序号010运行时第2次触发（grep过宽），已修复为awk模式；④序号003~009持续产生新检测项DET-006~014，形成"错误→检测项→角度"进化路径。本次任务中老板指出"维护债根因=改了规则没通读全文检查引用一致性，跟DET-007同一类"——正是ANGLE-022把维护债问题关联到已有检测项的应用。[军师验证通过 2026-08-14]

- 验证案例：本次脚本创建即首次验证——js-start.sh（开工脚本：读DET检测项+认知记忆+长期主题+最近执行记录+角度库规则+任务文件+计数器只读+预备份+N=3清理）和js-end.sh（收工脚本：diff+备份完整性检查+changelog模板+js-self-review模板+DET自检表动态生成+计数器+1+活动日志）创建成功，含DET分层读取、两轮审查修正全落实。[军师验证通过 2026-08-14]

  2. 机械步骤用脚本一键完成（开工脚本读文件+备份+计数器，收工脚本diff+模板）
  3. 半机械步骤用脚本生成模板框架，军师只填内容
  4. 真思考步骤不脚本化，军师专心做
  5. 脚本动态发现不硬编码，参数化不写死路径，保持纯bash无依赖

- 功能标签：执行中监控

- 可证伪条件：如果军师连续5次使用脚本执行但总执行时间没有减少（与手动执行时间差异<10%），说明脚本没有实际帮助，需评估角度有效性
- 非重复检查：与ANGLE-018成本效益有交叉但不同——ANGLE-018评估方案成本值不值，ANGLE-023优化执行流程本身。与ANGLE-022错误转检测项不同——ANGLE-022防错误，ANGLE-023提效率。核心问题不重叠

### 候选-实质审查（已拒绝入库，v2.13）
- **拒绝原因**：DET-002增强版检测方法已覆盖"检查所有数字参数是否都算了实际效果+数字与结论的逻辑链是否成立"，候选ANGLE-025的4条规则全是DET-002增强版的翻版，无增量认知价值。如果入库会造成"DET-002标通过→ANGLE-025再查一遍同样的事"的冗余。如果未来"形式合规≠实质有效"出现在非DET场景（如角度验证流程、整理流程），再重新提案。
- 名称：实质审查（形式合规≠实质有效）
- 核心问题：这个检测项/检查虽然"通过了"，但它真的起作用了吗？我检查的是"该检查的那个东西"吗，还是只检查了形式（有没有数字/有没有列路径/有没有加检查）而没检查实质（数字对不对/路径全不全/检查能不能真工作）？
- 拒绝日期：2026-08-15（老板批准拒绝）
- 触发场景：任何检测项/自检/检查标"通过"时，尤其涉及数字参数、文件清单、安全网机制时
- 来源：DET-002"形式合规实质失效"连续3次（序号007"10-20次"逻辑断裂/序号006-008算调用数没算tail窗口/序号009算脚本体积3KB没算输出体积14-165KB）。DET-002检测方法已增强，本角度把"形式合规≠实质有效"提升为独立认知角度
- 学习事件：军师每次自检DET-002都标"通过"（有数字有计算），但3次都没真正起作用——第1次数字与结论逻辑断裂，第2次算了A数字没算B数字（tail窗口），第3次把"脚本多大"当成了"脚本产出多大"。共同模式：检测项只检查"有没有X"（形式），不检查"X对不对/全不全/是不是该查的那个X"（实质）。根因=把"通过检测项"等同于"问题被解决"，对检测项本身过度信任
- 使用示例：DET-002标"通过"时追问3问——①我算的数字是不是该算的那个（如该算输出体积却算了脚本体积）②我列的路径是不是该读却没读的（如列了脚本涉及的文件却没查该读没读的longterm）③我加的检查/安全网自己有没有输入接口、能不能真工作（如加了备份完整性检查却没定义--modified怎么传入）
- 规则：
  1. 任何检测项/自检标"通过"时，必须追问"我检查的是不是该检查的那个东西"——不只问"有没有"，要问"对不对、全不全"
  2. 数字参数检查：不只检查"有没有数字和计算"，要检查"算的数字是不是该算的那个 + 数字与结论的逻辑链是否成立"
  3. 清单/路径检查：不只检查"有没有列出"，要检查"该列的都列了吗 + 该读却没读的有没有"
  4. 安全网/检查机制：不只检查"有没有加检查"，要检查"检查自己的输入接口定义了吗 + 它能真工作吗 + 它有什么盲区"
- 领域标签：通用
- 功能标签：执行中监控（对自检本身的自检）
- 使用次数：0
- 效果记录：无（待使用后补写。注：DET-002检测方法增强已先落实，本角度是增强的"角度化"提升）
- 对立假设验证：如果这个角度是错的（实质审查不需要），它会掩盖"过度自检导致效率下降"的问题——每个通过都要追问实质，自检成本翻倍。缓解：实质审查只在"涉及数字参数/文件清单/安全网机制"的高风险检测项上做，不对所有检测项机械追问；且追问聚焦"该检查的那个东西对不对"一个核心问题，不无限展开
- 可证伪条件：如果军师连续5次对"通过的检测项"做实质审查，但从未因此发现"形式合规实质失效"（每次实质审查都确认真的有效），说明形式合规与实质有效的差距已消除，本角度无增量价值，需评估有效性
- 非重复检查：与ANGLE-008防糊弄不同——ANGLE-008防"故意糊弄"（知假说真），本角度防"无意形式合规"（真心以为通过了但检查的不是该查的）。与ANGLE-024异常路径覆盖不同——ANGLE-024检查"异常路径下还成立吗"，本角度检查"正常通过时真的有效吗"（方向相反：一个查异常，一个查正常的真伪）。与DET-002不同——DET-002是具体检测项（数字阈值），本角度是把"形式合规≠实质有效"泛化为适用所有检测项的认知角度。核心问题不重叠
