## 一、角度库审视

### ANGLE-005 找盲区

秘书调研覆盖了5个维度（连接/上下文/大规模/状态/错误恢复），但**有3个盲区**：

**盲区1：并发冲突**
方案没有考虑"Agent操控浏览器时老板同时也在用同一个浏览器"的场景。Extension模式连接的是你正在用的Chrome——如果Agent在填表单时你切了标签页或者刷新了页面，Agent的element ref会失效。

**解法**：Agent操作时使用独立窗口（CDP的`--user-data-dir`指向Chrome profile的副本），而非直接操控当前标签页。或者约定"Agent工作时老板不碰浏览器"。

**盲区2：登录态过期**
几十步操作可能跨几小时。如果中途登录态过期（session timeout），Agent会卡在登录页面不知道怎么办。

**解法**：每个阶段开始前检查当前URL是否被重定向到登录页（`if current_url contains 'login' → pause and notify`）。

**盲区3：TRAE sandbox网络限制**
当前环境是远程sandbox。Playwright MCP的`npx @playwright/mcp@latest`需要在sandbox里执行，但浏览器在老板本地。Extension模式要求MCP server和Chrome在同一台机器上。

**解法**：这是最关键的约束。sandbox里的Agent不能直接连接老板本地的Chrome。需要额外一层桥接——要么在老板本地跑一个MCP server proxy，要么用WebSocket远程连接。

### ANGLE-017 反面论证

**如果"分阶段编排+子代理隔离"方案是错的，它会掩盖什么问题？**

它会掩盖"阶段间状态传递不可靠"的问题。每个子代理调用结束后，浏览器实例可能被回收（取决于MCP server实现）。如果storageState保存不完整（比如漏了sessionStorage），下一阶段加载状态时会丢失上下文，但Agent不会报错——它会以为状态完整然后做出错误操作。

**验证方法**：在阶段间不只保存storageState，还要保存当前URL+页面标题+关键DOM元素的文本。下一阶段开始时先验证这三项是否匹配，不匹配则报错而非继续。

### ANGLE-019 可逆性

浏览器状态回滚有两层：
- **会话级**：storageState save/load——可以回滚到某个检查点的cookies+localStorage
- **操作级**：无原生回滚——Playwright没有"undo click"的能力

**风险**：如果Agent在第30步做了错误操作（比如删了某条数据），storageState回滚只能恢复浏览器状态，不能恢复网站后端已变更的数据。

**结论**：方案必须区分"可逆操作"（导航/输入/点击导航类）和"不可逆操作"（提交表单/删除数据/支付）。不可逆操作前必须人工确认或保存pre-operation snapshot。

### ANGLE-022 错误转检测项

识别到3个可转DET的失败模式：

| 失败模式 | 转化为 | 检测方法 |
|---|---|---|
| element ref失效（页面变化导致） | DET-015候选 | 每次操作前检查ref是否存在，不存在则重新snapshot |
| 登录态过期 | DET-016候选 | 每个阶段开始检查URL是否被重定向到登录页 |
| 阶段间状态不完整 | DET-017候选 | 阶段开始时验证URL+标题+关键DOM文本三项匹配 |

**建议**：这3个先作为候选DET记录到coverage-gaps.md，等真实使用中累计≥3次再正式提案。

### ANGLE-003 全局看闭环

完整链路检查：

```
老板下指令 → 秘书拆阶段 → 子代理1执行阶段1 → 保存状态 → 子代理2执行阶段2 → ... → 子代理N执行阶段N → 返回结果 → 秘书翻译给老板
```

**断点1**：秘书拆阶段——怎么知道一个50步的任务该拆成几段？每段多少步？需要预估策略。
**断点2**：阶段间状态传递——已在ANGLE-017中指出风险。
**断点3**：错误恢复——某阶段失败后，是重试该阶段还是回滚到上一阶段还是终止？

**闭环方案**：
- 拆阶段策略：每段≤10步（单子代理上下文安全区），50步=5段
- 状态传递：storageState + checkpoint.json（URL+标题+进度数据）
- 错误恢复：3级策略（重试1次→回滚上一检查点→终止+返回已完成进度）

### ANGLE-024 异常路径覆盖

| 异常路径 | 是否覆盖 | 说明 |
|---|---|---|
| 浏览器崩溃 | 覆盖 | checkpoint + 重新启动浏览器 + 加载storageState |
| 网络断开 | 未覆盖 | 需要增加网络检测+等待重连机制 |
| 页面加载超时 | 部分覆盖 | Playwright有auto-wait，但无超时后的fallback |
| Agent决策错误（点了错按钮） | 未覆盖 | 需要不可逆操作前确认机制（ANGLE-019已指出） |
| 步骤数超预算 | 覆盖 | budget pressure机制（75%/90%警告） |
| 循环操作（Agent卡在翻页循环） | 覆盖 | spam detection（4次相同操作强制停止） |

## 二、完整技术方案

### 架构

```
主对话（老板 ↔ 秘书）
  │
  │ "执行50步浏览器任务"（~100 token指令）
  │
  ▼
秘书（编排层）
  │ 1. 拆分阶段（每段≤10步）
  │ 2. 依次派发子代理
  │
  ├──→ 子代理1：阶段1（步骤1-10）
  │    │ navigate → snapshot → click → ... → save_state
  │    │ 返回：{阶段1完成, checkpoint数据}（~200 token回主对话）
  │    ▼
  ├──→ 子代理2：阶段2（步骤11-20）
  │    │ load_state → verify → snapshot → ... → save_state
  │    │ 返回：{阶段2完成, checkpoint数据}
  │    ▼
  ├──→ ...（阶段3-N）
  │
  └──→ 最终结果返回老板（~200 token）
  
主对话总消耗：~500 token（5次调度×100 token）
子代理内部消耗：~5000 token/阶段（隔离在子代理内，不回主对话）
```

### 关键配置

**MCP配置（如果MCP server在本地运行）**：
```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest", "--extension"]
    }
  }
}
```

**Sandbox环境适配**：

由于TRAE在远程sandbox中运行，不能直接连接老板本地Chrome。需要以下方案之一：

| 方案 | 原理 | 可行性 |
|---|---|---|
| A. 本地MCP proxy | 老板本地跑一个HTTP MCP server，sandbox通过HTTPS连接 | 需要老板本地装Node.js |
| B. WebSocket隧道 | 老板本地Chrome开CDP端口，通过隧道暴露给sandbox | 需要隧道工具（如ngrok） |
| C. 纯sandbox浏览器 | 不连接老板本地Chrome，在sandbox里跑headless Chromium | 登录态需手动导入 |
| D. TRAE内置browser_use | 使用TRAE已有的browser子代理能力 | 最简单但不支持本地Chrome |

**推荐方案C**（短期可用）+ **方案A**（长期最优）：
- 短期：sandbox内跑headless Chromium + 手动导入cookies（`--storage-state`）
- 长期：老板本地跑MCP server proxy，sandbox远程连接

### 阶段间状态传递

```python
# 每个阶段结束时保存
checkpoint = {
    "phase": 2,
    "url": "https://example.com/dashboard",
    "title": "Dashboard - Example",
    "storage_state": "phase2_state.json",  # cookies + localStorage
    "progress": {"completed_steps": 20, "total_steps": 50, "extracted_data": [...]},
    "next_action": "Click 'Export' button to download report"
}

# 下一阶段开始时验证
assert current_url == checkpoint["url"]  # URL匹配
assert page_title == checkpoint["title"]  # 标题匹配
# 不匹配 → 报错，不继续
```

### 错误恢复策略

| 错误类型 | 恢复策略 | 升级条件 |
|---|---|---|
| element ref失效 | 重新snapshot + 重试 | 连续3次ref失效 → 报错 |
| 页面超时 | 等待5秒重试 | 3次超时 → 跳过该步骤 |
| 登录态过期 | 暂停 + 通知老板 | - |
| 阶段失败 | 重试1次 | 重试失败 → 回滚上一检查点 |
| 回滚后仍失败 | 终止 + 返回已完成进度 | - |

## 四、风险清单

| 风险 | 严重度 | 缓解策略 |
|---|---|---|
| sandbox无法连本地Chrome | 高 | 方案C（短期）+方案A（长期） |
