## 什么是"军师被调用"

军师被调用 = 秘书派发军师执行任务（提供方案、需求解决、分析事情、验证角度、整理提纯等）。

秘书什么时候派军师：需要军师做实质工作时才派（提供方案/需求解决/分析决策）。简单对话秘书自己回答，不派军师。

军师每次被调用时：
1. 自己把"军师被调用总次数"+1，写入本文件
2. 自己判断是否该触发meta-audit（到10次了没）
3. 自己判断是否该触发整理（到50次了没）
4. 该做就做，做完把结果返回给秘书
5. 秘书不参与计数、不参与判断、不参与触发

## 触发规则（军师自己判断自己执行）

- **计数触发meta-audit**：军师被调用总次数 - 上次meta-audit时的调用次数 ≥ 10 → 军师自己执行闭环7（meta-audit），不需要秘书派发
- **计数触发整理**：军师被调用总次数 - 上次整理时的调用次数 ≥ 50 → 军师自己执行整理（整理周期=50次军师调用），不需要秘书派发
- **调用即计数**：军师被调用本身就是心跳——军师自己+1，自己判断，自己执行。秘书不碰计数器
- 触发后军师自己更新对应的"上次触发时的调用次数"，重置距离计数

## 交叉验证规则（跳过检测，军师自己做）

军师执行meta-audit时自己检查：
1. 读取本文件的"军师被调用总次数"
2. 统计ms-standin-review.md的条目数（=闭环1自审次数）
3. 统计coverage-gaps.md的更新次数（=闭环2覆盖检查次数）
4. 计算：跳过闭环1次数 = 军师被调用总次数 - 自审次数。>0 = 秘书派了军师但没做自审
5. 计算：跳过闭环2次数 = 军师被调用总次数 - 覆盖检查次数。>0 = 秘书派了军师但没做覆盖检查
6. 计算：跳过闭环5次数 = 闭环4验证通过次数 - 闭环5入库次数。>0 = 验证通过但没入库
7. 跳过次数>0 → 本文件"进化引擎健康指标"小节记录预警 + issues.md追加"闭环跳过"问题 + dashboard标红

**循环引用检测**：未发现"A→B→A但都不含正文"的循环引用。三个文件之间的双向引用均为内容拆分后的互补指针引用——每个文件都包含实质正文（framework=角度清单，rules=管理规则，charter=职责定义+进化引擎），互相指向对方的正文内容，不是定义上的循环依赖。charter的11.2/11.9是纯指针引用指向rules，但rules引用charter的是charter含正文的10.2/11.5，属单向指针非循环。

**断链检测**：所有被引用的文件均存在，无指向不存在文件/章节的断链。
