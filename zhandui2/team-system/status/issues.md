### ISSUE-009: git仓库未初始化（冷启动检查P0）
冷启动检查闭环5验证发现：规则要求入库流程第1步"确认当前版本已提交到GitHub（git commit），作为可回滚基线"（charter 10.7），且v2.10已将备份机制切换为"GitHub统一管理，git checkout回滚"（rules"版本回滚"小节）。但实际执行`git status`返回"fatal: not a git repository (or any parent up to mount point /)"——`.team`目录及所有父目录均无git仓库。这意味着：①每次入库/整理后的git commit无法执行；②ANGLE-019"可逆性"原则失去技术保障——角度库改动无法通过git checkout回滚；③所有"修改前已备份到git"的变更记录声明（v2.8~v2.12文件头均写"修改前已备份vX.X到git"）实际未真正提交。修复建议：在`.team`目录执行`git init`+首次提交全部文件建立基线，后续每次军师执行后git commit。

### ISSUE-010: 闭环1自审记录格式缺列（冷启动检查）
冷启动检查闭环1验证发现：js-cognitive-rules.md"自审记录要求"小节（第78-82行）明确规定自审记录格式包含4个要素——①日期时间 ②场景描述（一句话）③使用的角度编号列表 ④每个角度的问题+回答+结论。但ms-standin-review.md的实际格式表只有4列：`| 角度编号 | 核心问题（一句话） | 回答（一句话） | 结论 |`，缺少"日期时间"和"场景描述"两列。影响：无日期则使用次数统计无法做时间维度分析（"老化检查"需90天无命中记录，"零使用角度判定"需30天入库时间判断，均依赖日期）；无场景描述则无法判断触发场景是否匹配角度（与覆盖检查闭环2联动失效）。修复建议：格式表增加"日期"和"场景描述"两列，或改为按"日期+场景"分组记录（每次自审一个日期+场景块，下面列多个角度）。

### ISSUE-011: 计数器表与活动日志不一致（冷启动检查）
冷启动检查闭环7交叉验证发现：js-dispatch-counter.md计数器表"军师被调用总次数"显示为7，但活动日志表有8行（序号1到8），其中序号8（2026-08-15）明确记录"计数器7→8"。说明js-end.sh执行时写入了活动日志第8行，但计数器表的"军师被调用总次数"未同步更新到8（仍为7）。可能原因：js-end.sh写日志和更新计数器表是两步操作，第8次执行时只写了日志没更新计数器表，或更新后被覆盖。影响：跳过差值计算基数错误（用7算跳过=7，实际应为8算跳过=8），dashboard显示的调用次数与实际不符。修复建议：校验js-end.sh计数器更新逻辑，确认计数器表与活动日志同步；本次冷启动检查不增加调用次数（规则明确"冷启动检查不增加军师调用次数"），计数器值待秘书确认后校正。
