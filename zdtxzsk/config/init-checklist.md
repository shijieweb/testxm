# Agent 启动检查清单

> 本文件由系统自动生成，也可由 Agent 手动维护。
> 每次开局时必读，确保状态一致。

## 开局三步

1. **[ ] 读偏好记录.md**
   - 获取称呼规则（如"称呼用户为老板"）
   - 获取工作规则（纠错复盘、进度管理、自检要求等）
   - 获取技术偏好（端口、路径、编码规范等）

2. **[ ] 读当前进度.md**
   - 文件存在且有实质内容 → 问老板"是否继续上次任务"
   - 文件只有占位符或不存在 → 正常开局，从头开始

3. **[ ] 确认项目上下文**
   - 调用 `/api/init` 获取角色+项目配置
   - 确认 persona、role、project 参数
   - 检查 knowledge/ 是否有相关条目可用

## 收尾三步

1. **[ ] 更新当前进度.md**
   - 如果任务未完成或跨会话 → 更新进度和下一步
   - 如果阶段完成 → 标记 milestone，清理已完成项

2. **[ ] 判断是否记录经验**
   - 完成任务中有价值的发现 → 追加到 `roles/{role}/experience.md`
   - 被用户纠正且有长期价值 → 追加到偏好记录.md（标[新增]）

3. **[ ] 生成纠错复盘**
   - 有被纠正的情况 → 写入 `纠错复盘/YYYYMMDD_原因_避免_补救.md`
   - 无纠正 → 跳过

## 经验记录触发条件

| 场景 | 操作 |
|------|------|
| 完成任务后有价值发现 | 追加到 experience.md |
| 被用户纠正且有长期价值 | 追加到偏好记录.md |
| 遇到新问题且有解决方案 | 追加到 experience.md |
| 一次性偶发问题 | 不记录 |
| 已知知识的重复 | 不记录 |

## 搜索知识最佳实践

- 有明确角色时传 `--role` 参数，缩小搜索范围
- 关键词尽量具体（2-4 字），避免单字匹配
- V1 限制：只搜索文件名+前200字符
- 无结果时检查是否传了正确的 role 参数
- 全局搜索不带 role 参数，搜索 knowledge/ 目录下所有条目
