## 问题：audit-log.md 格式混乱

### 原因
server.py 的 report 处理器每次追加新条目时，若 audit-log.md 已存在则以 prepend 方式写入，但不检查文件原始格式（是否以 `# 审核日志\n\n` 开头），导致新旧条目混排、标题出现在文件中间。

### 避免
- 首次写入时检查文件是否存在且是否以 `# 审核日志` 开头
- 若格式不对，先重写 header 再 prepend
- 或在 append 前先解析现有内容，保持 Markdown 标题层级正确

### 补救（本次已完成）
- 手动重写 `history/audit-log.md`，将提交记录和人工审核记录分段整理
- 新增"人工审核记录"章节，记录本次迁移决策和规则

## 问题：knowledge/ 目录始终为空

### 原因
V1 架构设计为 reports/ → 人工审核后迁入 knowledge/，但整个开发过程中从未执行过人工迁移步骤，导致 knowledge/ 作为查询目标目录一直是空的。

### 避免
- 在 server.py 或经验迁移流程中增加提示：当 query 不带 role 时命中 knowledge/ 为空，应在 README 或进度文档中标注
- 或 V1 中预填充若干基础条目到 knowledge/tools/ 和 knowledge/common/

### 补救（本次已完成）
- 本次将 ASKB Skill 端到端验证经验迁入 `roles/director/experience.md`
- 后续 V2 可考虑将工具使用指南类经验迁入 `knowledge/tools/`，使无 role 的泛查也能命中

## 问题：V1 关键词检索命中率低

### 原因
检索逻辑只匹配文件名 + 内容前200字符，导致深层内容（如角色职责的详细描述）无法被检索到。例如查询"经验沉淀"时，experience.md 中虽有相关内容但因位置超出前200字符而未命中。

### 避免
- V2 升级为全文检索或向量检索
- V1 可在 YAML 元数据中增加 `keywords` 字段，检索时同时匹配元数据和正文

### 补救（暂无，留作 V2 规划）
- 已在当前进度.md 的 V2 规划中列出此项
