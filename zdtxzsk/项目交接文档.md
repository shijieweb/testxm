## 一、项目概述

**ASKB（Agent System Knowledge Base）** 是一个为多智能体（Multi-Agent）协作系统提供知识管理与经验沉淀能力的轻量级 HTTP 服务。

核心价值：让多个 AI Agent 在工作过程中积累和复用经验，避免每次重启都从零开始。

**技术栈：**
- Python 3.10 + Flask（单文件服务器 `server.py`）
- pytest（TDD 测试框架，61 用例全绿）
- YAML（配置文件 + 知识文件 frontmatter）
- Markdown（所有知识库数据）

**运行地址：** `http://localhost:8765`
**项目根目录：** `c:\Users\67972\Documents\agentsystemwike\`

## 三、核心架构

### 3.1 数据流

```
Agent 启动
    │
    ▼
/api/init ──→ 加载 persona + role + project + 偏好 + 进度
    │              │
    │              ▼
    │         返回 context 字符串（≤6000字符）
    │
    ▼
Agent 工作中
    │
    ├─→ /api/knowledge/query ──→ 搜索 roles/ + knowledge/ + projects/ + KB_ROOT
    │
    └─→ /api/report ──→ 写入 reports/YYYYMMDD_agent_role_report.md
                         追加 history/audit-log.md（带去重+文件锁）
```

### 3.2 知识搜索范围

`find_knowledge_files()` 搜索以下目录（按优先级）：
1. `roles/{role}/` — 角色相关文件
2. `projects/{project}/knowledge/` — 项目专属知识
3. `knowledge/tools/` — 工具使用指南
4. `knowledge/common/` — 通用知识
5. `knowledge/projects/` — 项目知识
6. **KB_ROOT 自身** — 偏好记录.md、当前进度.md 等根目录文件

### 3.3 知识文件元数据格式

```markdown
---
title: 知识标题
date: 2026-08-22
scope: tools          # tools / common / projects
author: WorkBuddy
verified: false
tags: [tag1, tag2]
---
# 正文内容...
```

`scope` 字段决定知识分类：`tools`=工具指南，`common`=通用规范，`projects`=项目专属。

## 四、API 接口速查

### 4.1 GET /health
```bash
curl http://localhost:8765/health
# → {"status": "running", "kb_root": "c:\\Users\\67972\\Documents\\agentsystemwike"}
```

### 4.2 POST /api/init
```bash
curl -X POST http://localhost:8765/api/init \
  -H "Content-Type: application/json" \
  -d '{"agent":"workbuddy","persona":"strict","role":"director","project":"short-drama"}'
# → {"status":"ok","context":"...","files_loaded":["config/personas/strict.md",...]}
```
请求体：`agent`(必填), `persona`("strict"/"creative"/"guide"/"director"), `role`, `project`
响应：`context` 是拼接后的完整上下文字符串，`files_loaded` 是实际加载的文件路径列表

### 4.3 POST /api/knowledge/query
```bash
curl -X POST http://localhost:8765/api/knowledge/query \
  -H "Content-Type: application/json" \
  -d '{"query":"TDD","role":"director"}'
# → {"status":"ok","results":[{"path":"...","title":"...","scope":"...","tags":[...],"preview":"...","verified":false}],"count":2}
```
请求体：`query`(必填), `role`(可选过滤), `project`(可选过滤)
搜索逻辑：匹配文件名 or 内容前200字符 or YAML元数据

### 4.4 GET /api/knowledge/list
```bash
curl http://localhost:8765/api/knowledge/list
# → {"status":"ok","total":11,"items":[...]}
```

### 4.5 POST /api/report
```bash
curl -X POST http://localhost:8765/api/report \
  -H "Content-Type: application/json" \
  -d '{"agent":"workbuddy","role":"director","content":"修复了搜索bug"}'
# → {"status":"saved","path":"reports/20260824_workbuddy_director_report.md","filename":"..."}
```
写入后自动追加到 `history/audit-log.md`（带去重和文件锁）

### 4.6 GET /api/metrics
```bash
curl http://localhost:8765/api/metrics
# → {"status":"ok","total_requests":42,"kb_root":"...","uptime_seconds":1234.5}
```

## 六、配置说明

### config.yaml 关键配置项

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `server.max_context_chars` | 6000 | init 返回 context 最大字符数 |
| `server.lock_timeout` | 5 | 文件锁等待超时（秒） |
| `server.log_level` | INFO | 日志级别 |
| `paths.server_port` | 8765 | HTTP 服务端口 |
| `paths.server_host` | 0.0.0.0 | 绑定地址 |
| `defaults.persona` | strict | 默认人格 |

### 环境变量覆盖
- `KB_ROOT` — 覆盖知识库根目录（测试时用）
- `SERVER_PORT` — 覆盖端口
- `SERVER_HOST` — 覆盖绑定地址

## 七、常见问题与快速诊断

### Q1: 服务启动失败
```bash
# 检查端口是否被占用
netstat -ano | findstr :8765
# 停止占用进程后重启
python stop_server.py; python server.py
```

### Q2: init context 为空或截断
- 检查 `config/personas/{persona}.md` 是否存在
- 检查 `max_context_chars` 配置是否合理（当前6000）
- 查看日志确认加载了哪些文件

### Q3: query 返回空结果
- 确认搜索关键词在文件名或内容前200字符内
- 确认目标文件有 YAML frontmatter（title/scope/tags）
- 检查 `find_knowledge_files` 的 search_dirs 是否包含目标路径

### Q4: audit-log 重复条目
- 当前去重逻辑：相同 agent/role 在最近20条中已存在则跳过
- 如需强制写入，修改 `recent_lines` 范围或清空 audit-log.md

### Q5: pytest 跨文件 KB_ROOT 污染
- 每个测试文件应显式调用 `set_kb_root()` 设置自己的 KB 路径
- 不要依赖其他测试文件的 fixture 状态
